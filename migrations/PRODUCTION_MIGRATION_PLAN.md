# Production DB Migration Plan

Goal: Add missing interview columns to the production database safely and trackably using Alembic.

Summary:
- Use Alembic for schema migrations in production (recommended).
- Provide a reversible migration that adds the columns: `candidate_name`, `position`, `interviewer`, `notes`, and `scheduled_at` if missing.
- Test the migration in a staging environment before running in production.

Steps (high level):
1. Add Alembic to the project if not present: `pip install alembic` and run `alembic init alembic`.
2. Configure `alembic.ini` and `alembic/env.py` to use the application's SQLAlchemy `DATABASE_URL` and model `MetaData`.
3. Create a migration revision: `alembic revision -m "add interviews columns" --autogenerate` and inspect the autogenerated script.
4. If autogenerate won't detect columns (e.g., due to SQLite specifics), write a manual migration using SQLAlchemy `op.add_column()`.
5. Test migration on a copy of production DB (or staging). Run `alembic upgrade head` and verify.
6. Run in production during a maintenance window; ensure backups exist.

Example Alembic migration (manual):

```py
from alembic import op
import sqlalchemy as sa

# revision identifiers, used by Alembic.
revision = 'add_interview_columns_001'
down_revision = None
branch_labels = None
depends_on = None


def upgrade():
    # Add columns if they don't exist (DBs like Postgres will error if column exists, so
    # guard checks may be needed when writing raw SQL in some backends).
    op.add_column('interviews', sa.Column('candidate_name', sa.String(length=255), nullable=True))
    op.add_column('interviews', sa.Column('position', sa.String(length=255), nullable=True))
    op.add_column('interviews', sa.Column('interviewer', sa.String(length=255), nullable=True))
    op.add_column('interviews', sa.Column('notes', sa.Text(), nullable=True))
    # If `scheduled_at` is missing and you currently store date/time separately, migrate carefully.
    # Example for a datetime column:
    op.add_column('interviews', sa.Column('scheduled_at', sa.DateTime(), nullable=True))


def downgrade():
    op.drop_column('interviews', 'scheduled_at')
    op.drop_column('interviews', 'notes')
    op.drop_column('interviews', 'interviewer')
    op.drop_column('interviews', 'position')
    op.drop_column('interviews', 'candidate_name')
```

Notes and precautions:
- For Postgres, `op.add_column` is safe for online migrations but test locking behavior under load.
- For MySQL, index and type changes may require more manual steps.
- For SQLite, Alembic may need to recreate tables for complex changes; test carefully.
- Always take a DB backup before running migrations in production.

Recommended checklist before production run:
- [ ] Create a staging DB snapshot and run migration.
- [ ] Run full test suite against migrated schema.
- [ ] Notify stakeholders and schedule maintenance window.
- [ ] Run migration and verify application health.
